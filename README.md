# 大和川 河合観測所 水位アラート

大和川「河合」観測所（観測所記号 306031286607020）の水位が、次のしきい値以上になったら、
スマホ（ntfyアプリ）に通知が届く仕組みです。GitHub Actions で自動実行されるので、
自分のPCやスマホを起動しておく必要はありません。

しきい値: **-1.3 m / -1.2 m / -1.1 m / -1.0 m**（それぞれ、初めて超えたときに1回ずつ通知）

藤井観測所など、他の観測所の仕組みとは別のリポジトリ・別の通知先（トピック）で動かします。

## あくまで補助的な手段です

通知は、取得先の制限・プログラムの障害・GitHubやntfyの障害・スマホの設定や圏外などで
届かないことがあります。**通知が来ないことをもって安全と判断しないでください。**
現場での目視確認と気象・河川情報の確認を続け、退避は定めた基準に従って判断してください。

## データの取得元について（重要）

取得元は国土交通省の「水文水質データベース」（www1.river.go.jp）です。
このサイトには「ツール等による自動的なデータ収集等は、サーバに負荷がかかるため、
原則としてご遠慮ください」という趣旨の注意書きがあります。
本プログラムの自動取得はこれに該当する可能性が高いため、**利用にあたっては発注者
（河川事務所）等に確認してください。**
なお「川の防災情報」（river.go.jp/kawabou）のページにはアクセスしていません。

アクセス量は、1回の実行あたり2リクエスト、30分おき（日本時間7〜18時）です。
公式に提供されている有料配信（河川情報センターの水防災オープンデータ提供サービス）もあります。

## 仕組み

1. 30分おきに、河合観測所の「リアルタイム10分水位」ページと、そのデータ(.dat)を取得
2. ページに書かれた観測所記号・観測所名が設定と一致するか照合（一致しなければ通知せずエラー）
3. しきい値を初めて超えたとき、その段階の通知を1回だけ送信
4. 水位がしきい値を下回ると記録をリセット（次に超えたとき、また通知）
5. 取得や通知に失敗した回は、GitHub の Actions 画面で赤い✕になる

一度に複数のしきい値を超えた場合は、超えた段階の数だけ通知が届きます。

## ファイル構成

- `check_water_level.py` … 本体。冒頭の `STATIONS` で観測所・しきい値を設定
- `.github/workflows/check_water_level.yml` … 実行スケジュール（30分おき、日本時間7〜18時）
- `data/state.json` … 通知済みのしきい値や最新の水位の記録（自動更新・手で触らない）
- `requirements.txt`

## セットアップ（初回のみ）

1. **ntfyのトピック名を決める**（他の仕組みで使っているものとは別の、長めのランダムな文字列）。
   スマホのntfyアプリで、このトピック名を購読する
2. GitHub で新しいリポジトリを作り、このフォルダの**中身**（`check_water_level.py`、
   `requirements.txt`、`README.md`、`data` フォルダ、`.github` フォルダ）をアップロードする
   （フォルダごとではなく、中身をアップロード）
3. リポジトリの `Settings` → `Secrets and variables` → `Actions` → `New repository secret` で、
   Name に `NTFY_TOPIC`、Secret に手順1のトピック名を登録する
4. `Settings` → `Actions` → `General` → `Workflow permissions` を
   「Read and write permissions」にして保存する
5. `Actions` タブ → `Yamato river Kawai water level check` → `Run workflow` で手動実行し、
   緑のチェックになること、`data/state.json` が更新されることを確認する

## 設定の変更

- **しきい値を変える**: `check_water_level.py` 冒頭の `STATIONS` の `thresholds` を書き換える
- **監視する時間帯・間隔を変える**: `.github/workflows/check_water_level.yml` の `cron`（UTC基準）を変更する

## 止まっていないかの確認

- GitHub の `Actions` タブで、直近の実行が緑のチェックになっているか確認する
- `data/state.json` の `last_checked`（最後に確認した時刻）と `last_error`（`null` なら正常）を見る
- 赤い✕のときは、実行結果の「Check water level」のログに理由が出ます
